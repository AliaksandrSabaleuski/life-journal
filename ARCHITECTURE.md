# Архитектура приложения (трекер привычек / дневник)

Документ фиксирует целевую архитектуру приложения. Текущая реализация в `main.dart` (экран событий за день) будет постепенно заменена на UI главного меню по макету и разнесена по слоям и фичам.

---

## 1. Общая идея

- **Цель**: офлайн‑первое приложение для отслеживания привычек с календарём, статистикой, помощником, настройками, опциональной подпиской. Отдельная сущность — **привычка** (habit): планируется преднастроенный набор + возможность добавлять свои (этап добавления своих привычек пока не делаем, держим в уме).
- **Подход**: структура по фичам (`features`) + общий слой `core`, поверх Flutter `MaterialApp`.
- **State‑management (на будущее)**: Riverpod (или аналог) для отделения UI от бизнес‑логики и упрощения подписки, аналитики, первого входа.

---

## 2. Главное меню (основное окно приложения)

Главный экран — это **мейн меню** по макету. Сначала делаем только UI без реальных записей.

### 2.1 Верхняя панель (AppBar)

| Элемент        | Расположение | Назначение                          |
|----------------|--------------|-------------------------------------|
| Кнопка настроек | Слева        | Открывает экран настроек            |
| Поле поиска    | По центру    | Поиск по привычкам (пока заглушка)  |
| Кнопка подписки | Справа       | Экран про подписку / paywall        |

### 2.2 Основной контент (скролл)

- **Список карточек привычек**  
  Каждая карточка: круглый прогресс с иконкой (слева), название привычки, метрики: «Текущая цель», «Попытка», «Рекорд» (в днях). Данные пока заглушки / мок.
- **Блок «Новое»**  
  Плейсхолдер под будущий контент (например, добавление новой привычки или рекомендации).
- **Мотивационный текст**  
  Например: «Ключи к более продуктивному образу жизни в ваших руках. Начните новую привычку сегодня!»

### 2.3 Нижняя навигация (Bottom navigation)

- **Вкладка «Календарь»** — переход к экрану календаря.
- **Вкладка «Статистика»** — переход к экрану статистики.
- **Вкладка «Помощник»** — переход к экрану помощника.
- **Кнопка «+»** — добавление новой привычки (пока заглушка или неактивна, т.к. этап добавления своих привычек отложен).

Итого: один shell-экран с верхней панелью, контентом главного меню и нижними вкладками; контент переключается по вкладкам (главное меню / календарь / статистика / помощник).

---

## 3. Дополнительные флоу и фичи (в архитектуре)

Учитываем в структуре, реализацию — по этапам:

- **Первый вход (onboarding)** — отдельный флоу при первом запуске (экраны приветствия, возможно выбор предустановленных привычек).
- **Аналитика** — сбор событий и метрик (открытие экранов, действия пользователя), без привязки к конкретному backend’у на старте.
- **Звуки** — воспроизведение звуков (например, при отметке привычки), настройка в настройках.
- **Кастомные иконки** — для привычек: предустановленный набор + в перспективе свои иконки.

Сущность **привычка** предполагается с полями вроде: id, название, иконка, цвет/тип, цель (дни), текущая попытка, рекорд; источник — предустановленный список и (позже) пользовательские привычки.

## 5. Слои и обязанности

### 5.1 Presentation (UI)

- Только отображение и пользовательские действия.
- Не знает, где хранятся данные; вызывает методы контроллеров/провайдеров.
- Примеры:
  - `main_shell.dart` — верхняя панель (настройки, поиск, подписка), нижние вкладки, переключение контента.
  - `main_menu_content.dart` — список карточек привычек, блок «Новое», мотивационный текст.
  - `calendar_screen.dart`, `stats_screen.dart`, `assistant_screen.dart` — контент вкладок.

### 5.2 Application / Controllers (state)

- Состояние и бизнес‑логика фичи.
- Общение с репозиториями и сервисами.
- Кандидаты для Riverpod StateNotifier/Notifier или ChangeNotifier.
- Примеры:
  - `main_menu_controller.dart`: список привычек для отображения (пока мок), фильтр поиска.
  - `settings_controller.dart`: тема, язык, звуки, кастомные иконки.
  - `onboarding_controller.dart`: шаг онбординга, флаг «первый вход выполнен».

### 5.3 Repositories (доступ к данным)

- Один источник правды для данных: локальная БД, SharedPreferences, позже API.
- Application-слой не знает деталей хранения.
- Примеры:
  - `HabitsRepository`: получение списка привычек (предустановленные + позже пользовательские).
  - `HabitRecordsRepository`: отметки по дням для календаря и статистики.
  - `SettingsRepository`: тема, язык, звуки, настройки иконок.

### 5.4 Services (инфраструктура)

- Низкоуровневые вещи: `LocalStorage`, `SoundPlayer`, `AnalyticsService`, в будущем `AuthService`, `BillingService`.

## 6. Как текущий код ложится в архитектуру

- Сейчас: `JournalApp` и `TodayEventsPage` в `main.dart` (календарная полоса и список событий за день).
- План:
  1. Ввести **shell**: `MainShell` с AppBar (настройки слева, поиск по центру, подписка справа) и нижней навигацией (Календарь, Статистика, Помощник, +).
  2. Контент по умолчанию — **главное меню**: список карточек привычек (мок), блок «Новое», мотивационный текст; без реальных записей.
  3. Календарь/статистика/помощник — отдельные экраны-заглушки внутри того же shell.
  4. Вынести состояние главного меню в контроллер, хранение привычек — в репозиторий, общие виджеты — в `core/widgets`.
  5. **Настройки**: экран настроек, контроллер, репозиторий (тема, язык, звуки, иконки); кнопка в AppBar открывает экран.
  6. **Онбординг**: проверка первого входа в роутере, экран онбординга, затем переход на `MainShell`.
  7. Аналитика, подписка, остальные фичи — по приоритету.

Сущность **привычка** и сценарий «предустановленные + пользовательские привычки» в коде пока только закладываем (модель, репозиторий, плейсхолдеры в UI), без полноценного добавления своих привычек.

## 7. Этапы внедрения (кратко)

1. **Shell и главное меню (только UI)**  
   Создать `MainShell`, `MainMenuContent`, заглушки для календаря, статистики, помощника. Вверху — настройки, поиск, подписка; внизу — вкладки. Данные привычек — мок.
2. **Вынести приложение и роутинг**  
   `app/app.dart`, `app/router.dart` (проверка первого входа пока заглушка).
3. **Модель и репозиторий привычек**  
   `Habit`, `HabitsRepository` (пока только предустановленный набор или мок).
4. **Контроллер главного меню**  
   Подключить список привычек из репозитория/мока к UI.
5. **Функционал настроек**  
   Экран настроек, `SettingsController`, `SettingsRepository`: тема, язык, звуки, кастомные иконки (по мере необходимости). Кнопка «Настройки» в shell ведёт на этот экран.
6. **Онбординг**  
   Флоу первого входа: проверка в роутере, `OnboardingScreen`, сохранение флага «онбординг пройден», переход на `MainShell`.
7. **Всё прочее**  
   Аналитика, подписка, календарь/статистика/помощник с реальными данными, добавление пользовательских привычек и т.д. — по приоритету; места в архитектуре зарезервированы.

Этот документ не требует немедленной реализации всего перечисленного, но служит ориентиром: новые фичи и экраны укладываем в эти слои и каталоги.
